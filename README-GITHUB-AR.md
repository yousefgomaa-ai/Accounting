# ملفات ميزان — رفع المشروع على GitHub وتشغيله

هذه ملفات المصدر الكاملة للنسخة الثانية: تطبيق React/Vinext يعمل بخادم Cloudflare Worker وقاعدة بيانات Cloudflare D1، مع مخطط البيانات والترحيلات والاختبارات. لا توجد بيانات شركات أو كلمات مرور أو مفاتيح أو مجلدات node_modules ضمن الحزمة.

## الرفع إلى GitHub

1. فك ضغط Mizan-Website-GitHub.zip.
2. أنشئ مستودعًا جديدًا فارغًا في GitHub.
3. ارفع محتويات مجلد المشروع إلى جذر المستودع، بما فيها .gitignore و.npmrc ومجلد .openai. لا ترفع ZIP وحده إذا أردت عرض الكود والعمل عليه.
4. يفضّل استخدام Git أو GitHub Desktop لرفع كل الملفات والمجلدات، بما فيها الملفات التي تبدأ بنقطة. الحزمة لا تحتوي مجلد .git أو تاريخ المستودع السابق.

GitHub مستودع للكود. GitHub Pages استضافة ثابتة ولا تشغّل واجهة /api/desk أو قاعدة البيانات في هذا المشروع. لن يكفي رفعه على Pages لتشغيل الدفاتر والحفظ.

## متطلبات التشغيل المحلي

- Node.js 24 LTS موصى به، خصوصًا لاختبارات node:sqlite. الحد الأدنى المعلن للمشروع 22.13.
- npm، واتصال لتنزيل الحزم.
- من داخل مجلد المشروع:

```bash
npm ci
npm run build
node scripts/apply-local-migrations.mjs
npm run dev
```

افتح http://localhost:5173 ثم استخدم «تسجيل الدخول». في وضع التطوير المحلي فقط، يوفّر القالب مستخدم اختبار ثابتًا. هذا ليس دخول ChatGPT حقيقيًا ولا يجوز استعماله كحماية لموقع منشور. التطوير المحلي يتطلب عنوان localhost أو 127.0.0.1 ويحتفظ ببياناته في مجلد .wrangler المحلي غير المتعقب.

يشغّل مساعد الترحيل SQL المضمن مرة واحدة لكل قاعدة محلية، ويسجل بصماتها. لا تعدّل ترحيلًا سبق تطبيقه؛ أضف ترحيلًا جديدًا. عند إنشاء قاعدة محلية جديدة أعد تنفيذ الخطوة بعد البناء.

## التحقق

```bash
node --test tests/accounting.test.mjs
node tests/runtime-integration.mjs
npx tsc --noEmit
npm run build
```

اختبارات الحسابات تتضمن 20 حالة. اختبار وقت التشغيل ينشئ قاعدة اختبار مستقلة، ثم يفحص الحفظ بعد إعادة تشغيل Worker. لا تُنشر tests/runtime-worker.mjs كعامل الإنتاج؛ إنه أداة اختبار فقط.

## نشر الموقع الحقيقي

النسخة المنشورة الحالية تعتمد على إدارة Sites لتوفير:

- Cloudflare D1 باسم الربط DB.
- تطبيق ترحيلات drizzle بالترتيب قبل تشغيل الخادم.
- دخول ChatGPT وتمرير معرف الزائر وبريده بصورة موثوقة إلى الخادم.

مجلد .openai يضم تعريف ربط DB ومعرف الموقع الحالي، وليس بيانات دخول. وجوده لا يمنح حق دخول الحساب أو قاعدة البيانات.

إذا ستستخدم الاستضافة نفسها المرتبطة بـ Sites، احتفظ بملفات التكامل وتعريف الموقع. نسخة GitHub تحفظ المصدر ولا تزامن تلقائيًا مع رابط الموقع الحالي.

إذا ستنشر بشكل مستقل خارج Sites، يلزم إعداد Worker/D1 وربط قاعدة إنتاج، وإضافة نظام دخول موثوق أو طبقة تتحقق من الهوية قبل تمريرها. ملفات app/chatgpt-auth.ts وapp/api/desk/route.ts توضح الاعتماد على هوية المنصة. لا تعتمد على رؤوس يرسلها الزائر مباشرةً، ولا تثبت معرف مستخدم في الكود، ولا تنشر الموقع بدخول الاختبار المحلي. التشغيل المستقل الآمن يحتاج تكييف هذه الطبقة؛ هذه الحزمة ليست إعداد نشر مستقل مكتملًا بضغطة واحدة.

لا تُشغّل قاعدة إنتاج أو تمرر بيانات اعتماد في متصفح الزائر. لا ترفع .env أو .dev.vars أو قاعدة البيانات المحلية إلى GitHub.
